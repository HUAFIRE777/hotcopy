# 刚需主链路：提炼重点 → 单平台脚本/分镜（设计）

日期：2026-09-24　状态：已与产品负责人逐项确认

## 目标

面向国内自媒体博主，把「贴链接 → 拿到可直接录制的中文平台稿」做稳定、做省。先求稳定和成本可控，高并发（任务队列、多实例）不在本期。

## 已确认的产品规则

1. **只提炼重点，不做金句。** 输出「一句话主旨 + 3–6 条重点（每条附原文依据/数据）」。
2. **单选平台，一次调用。** 平台四选一：抖音、小红书、B站、视频号；形式二选一：口播稿、分镜表。第一次请求一次模型调用同时输出「重点 + 所选平台成稿」。
3. **后续改写不重发全文。** 换平台、或只用勾选的重点重写，只把已保存的重点发给模型。
4. **计费：**
   - 用户第一次处理某个视频：按时长每 30 分钟 1 次（向上取整，最少 1 次），包含第一份成稿（或原声全文）。
   - 同一视频再生成新的平台稿 / 形式 / 重点组合 / 中文翻译：每项 1 次。
   - 用户自己已经拿到过的结果再次打开：0 次。
   - 全站共享缓存：别人生成过的结果，新用户拿到也扣 1 次（与时长无关）；模型调用 0 次。
   - 生成失败、中途中断：不扣次数，不写缓存。
   - 需要扣 2 次及以上时，先返回所需次数，用户确认后再扣。
   - 免费用户只能处理 30 分钟以内的视频。
5. **中文翻译为可选项**，不默认生成；只对 30 分钟以内的视频开放，按段分批翻译，不再截断。
6. **热点卡片不预生成**，用户点击才生成。
7. **Premium 月额度 300 → 250**（前台价格页、Creem 发货、后台手动升级同步修改）。

## 实测依据（2026-09-24，线上 Groq 账号）

- 账号为免费档 `on_demand`：千问 3.8 每分钟 8000 token、每分钟输出 1000 token；Whisper 每小时 7200 音频秒。
- 16.6 分钟英文视频：Whisper V3 4.6 s，Turbo 1.5 s，两者文本几乎一致；千问改写一次输入 4218 / 输出 1146 token，无思考 token。
- 第二次连续调用即返回 429（输出 token 每分钟上限）。
- 成稿问题：千问把原博主经历写成第一人称「我」、开头有「以下是为你定制」等废话；gpt-oss 把赞助口播写进要点。

## 架构

`backend/server.js` 解冻，只保留路由；新增 `backend/core/` 小模块，均可单测：

| 模块 | 职责 |
|---|---|
| `core/llm.js` | `chatStream()`：SSE 按行缓冲解析（修丢字）；模型顺序 `LLM_MODEL → openai/gpt-oss-120b → openai/gpt-oss-20b`；429 / 5xx / 网络错误 / 首字节 60 秒超时即换下一个模型；流开始后失败抛错交给调用方；返回全文、所用模型、token 用量 |
| `core/billing.js` | 时长→次数；按字数估算时长（缺时长时兜底）；`user_unlocks` 表记录用户已拿到的结果；原子扣减（`UPDATE … WHERE used_count + ? <= monthly_limit`）与失败退还 |
| `core/prompts.js` | 首次生成、重点重写、翻译分段的提示词；四平台 × 两形式的风格要求；通用规则（只输出成稿、原博主经历写成「原博主」、删除赞助/广告/求关注、保留事实与数字、不编造） |
| `core/points.js` | 从首次生成的 Markdown 中解析「主旨 + 重点」，生成稳定 ID，计算所选重点的哈希 |
| `core/usage_log.js` | `usage_log` 表：用户、视频、动作、扣次、模型、输入/输出 token、转写模型与音频秒数；管理端汇总 |
| `core/pipeline.js` | 业务编排（依赖注入，便于测试）：取逐字稿 → 计价 → 确认 → 调模型 → 写缓存/解锁/日志 |

## 接口

- `POST /api/script { url, platform, format, point_ids?, confirm? }` → 流式纯文本。
  - 无已存重点：读逐字稿，一次调用输出主旨+重点+成稿，结束后解析保存重点。
  - 有已存重点：只把重点（或勾选的重点）发给模型写成稿。
  - 需确认时返回 `409 { needs_confirm: true, credits, duration_minutes }`。
  - 响应头 `X-Credits-Charged`，结束后前端刷新额度。
- `GET /api/script/points?url=` → 已存的主旨与重点（用于勾选；不扣次数，需该用户已解锁该视频）。
- `POST /api/generate { url, mode }` 保留：`raw`、`translate`（新规则）；`summary`、`rewrite` 旧模式保留兼容但前端不再调用；统一使用 `core/llm.js` 与新计费。

## 逐字稿与时长

- 新表 `media_meta(video_id, duration_sec, source, title, updated_at)`。
- 时长来源：YouTube 字幕取 VTT 最后一条时间；B站字幕取最后一条 `to`；需要转写时，音频下载压缩后用 `ffprobe` 取时长，**在调用 Whisper 之前**做免费用户 30 分钟限制与扣次确认，避免白花转写费用。
- 旧缓存没有时长：英文按 1070 字符/分钟、中文按 250 字/分钟估算。
- Whisper 顺序改为 **Turbo → V3**；TikTok 转写也走统一函数；记录音频秒数。
- `transcribeLongAudio` 改用 `execFile` 参数数组（修复链接拼进 shell 命令的注入风险）。

## 缓存

- 缓存键：`raw`、`points`、`script:<platform>:<format>:<重点哈希|all>`、`translate`。
- 现有「全表只保留 200 行」的清理会把共享缓存和逐字稿清掉，改为按时间清理（成稿 30 天、逐字稿 60 天）。
- 只有完整生成成功才写缓存。

## 前端（`frontend/index.html`）

- 首页主按钮改为「生成平台稿」：上方平台四选一（带 Logo，localStorage 记住上次选择）+ 形式二选一。
- 四宫格改为：原声全文、中文翻译（可选，30 分钟内）、生成平台稿（主按钮）；去掉「核心要点」卡片与结果弹窗中的对应标签。
- 结果弹窗：流式显示；生成完成后显示重点勾选列表、「用勾选重点重写」和「换平台」按钮；409 时弹确认框显示所需次数。
- 价格页 Premium 改为每月 250 次。

## 错误处理

统一中文提示：链接无效、无字幕且无人声、视频超过免费时长、额度不足、模型繁忙（所有模型都 429 时提示稍后再试）、生成中断（已退还次数）。

## 测试

node:test 单测：SSE 跨块不丢字、429/超时换模型、流中断抛错、时长→次数与估算、解锁规则（首次/新项/已拿到/共享缓存）、原子扣减不超额与退还、重点解析与哈希、提示词包含平台规则、pipeline 各分支（确认、失败不扣、缓存命中）。最后在服务器用真实视频跑通四个平台各一次。

# HotCopy 核心链路状态（2026-09-26）

## 已接通

- 粘贴 YouTube、B站、TikTok、Apple Podcasts 或小宇宙链接后提交持久化任务；刷新页面后仍可用任务 ID 查询。
- 后端 SQLite 队列有全局并发上限、单用户待处理上限、任务租约和进程异常后的领取机制。默认全局 2 个任务、单进程 1 个任务；可用 `HOTCOPY_MAX_RUNNING`（1–16）和 `HOTCOPY_LOCAL_CONCURRENCY`（1–8）调整。现有 VPS 约 1 GB 内存且运行其他服务，所以先保守串行。这是保护阀，实际容量取决于 Groq 限额、ISP 出口、CPU、磁盘与视频长度。
- 已知时长后才扣次；按 30 分钟进位的方案由 `HOTCOPY_ENABLE_UNIT_BILLING=1` 对**新注册用户**开启，既有用户维持旧计次。2 次及以上先确认；取消、失败后释放预留次数。同一用户同一来源同一结果重看不重复扣次；其他用户命中缓存收 1 次。
- 原文、要点、翻译和 AI改成经同一任务链。AI改成可选平台、形式、模型与重点，换选项生成独立缓存键。字幕优先，必要时才取音频并转录；YouTube 匿名优先，认证故障才按出口使用 Cookie。
- 每个成功或失败任务记录模型 Token、听写秒数、音频字节和提供商标价估算；后台可查看新任务记录。代理流量、VPS、支付手续费和退款尚未计入，故不展示利润。
- 页面上的本地音频上传入口暂时关闭，因为上传接口尚未接入持久化队列。当前只开放内容链接。

## 本地验证

在 `backend/` 执行：

```bash
node --test core/*.test.js youtube_cookie_pool.test.js youtube_transcript.test.js youtube_innertube.test.js
```

测试包括 SQLite 跨连接并发上限、去重、按时长扣退、确认过期、失败退款、任务所有权、HTTP 提交与查询、模型 mock 生成、重点再生成，以及 YouTube 匿名/出口/Cookie 回退。另在本地浏览器注册一次性测试账号，点击一条预置缓存的 YouTube 测试链接，看到“等待处理”变为“处理完成”、原声文本出现并计入 1 次。它们不验证真实 Groq、ISP、VPS、YouTube 的实时可用性。

## 上线前实测

1. 用一条 5–10 分钟公开视频测字幕路径；记录总耗时、出口、是否调用 Whisper、模型 Token 与结果准确度。
2. 用一条无字幕且可合法处理的长视频测音频路径；记录音频字节、代理出口流量、Groq 实际账单与失败类型。
3. 模拟一个 ISP 出口断线、一个 Cookie 认证失败、Groq 429、工作进程在扣次后重启，检查切换、续领和无重复扣次。
4. 在预期峰值下逐步压测，观测队列等待、成功率、95 分位耗时、Groq RPM/TPM、出口带宽和 VPS 磁盘。达到稳定目标后再定并发值。
5. 从服务商账单补齐 ISP、VPS 和支付成本，再定按次价格。Groq 模型价格应以[官方模型表](https://console.groq.com/docs/models)及[语音文档](https://console.groq.com/docs/speech-to-text)的当时价格复核。

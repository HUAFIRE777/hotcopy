# YouTube 凭证维护

HotCopy 的主服务、Whisper 音频回退和雷达的 yt-dlp 回退使用三个独立的 Cookie 文件位置：主用、备用一、备用二。只有 yt-dlp 明确返回登录或 Cookie 失效错误时才尝试下一个位置；视频下架、地区限制及一般网络错误不会触发账号轮换。三套都无法认证时再试公开视频模式，随后仍按原来的字幕库与 Whisper 链路降级。备用账号无法解决服务器 IP 被限制的问题。

## 首次配置与更新

1. 为主用和两个备用位置分别准备专用 YouTube 账号。不要把同一个账号的同一份 Cookie 复制三次。
2. 对每个账号分别打开新的无痕窗口，登录 YouTube，在同一窗口打开 `https://www.youtube.com/robots.txt`，导出 `youtube.com` 的 **Netscape 格式** Cookie 文件，然后关闭无痕窗口。不要重新打开这个会话。
3. 登录 `https://hotcopy.eazyopc.com/manage-777`，进入「YouTube 凭证与备用切换」，选择相应位置，粘贴完整文件内容并保存。服务器会先运行公开视频探针；探测未通过时旧文件保持不变。
4. 点击「检测全部凭证」，确认三张状态卡为「探测通过」。后台只显示状态和时间，不回显 Cookie 内容。

Cookie 保存在服务器 `/opt/hotcopy/` 下，文件权限应为 `0600`。不要把 Cookie 发到聊天、邮件、工单或 Git 仓库。`backend/.env.example` 可配置三个路径；未设置时使用 `/opt/hotcopy/cookies.txt`、`cookies-backup-1.txt`、`cookies-backup-2.txt`。更新成功后无需重启服务。

## 看懂状态

- **探测通过**：当前服务器能用该文件访问固定测试视频；这不保证所有视频都可用。
- **待检测**：文件存在但尚无本进程的实际探测结果，不代表可用。
- **认证失败**：明确的登录/会话失败。系统会在后续提取中暂时跳过该文件并尝试下一套；更新文件后会重新测试。
- **请求受限/探测失败**：需检查网络、请求频率或视频源；不要盲目轮换账号。
- **上次使用/上次切换**：表示实际提取请求最近选用的账号，不是探针检查顺序。

服务启动约一分钟后会开始后台探测，之后约每六小时复查。管理员也可手动逐个探测。探针使用固定公开视频 `TbkUKCm3CHQ`；若原作者改变该视频的可用性，探测结果也会受影响，需要先排查探针而不是立即认定三套账号同时失效。

yt-dlp 官方明确说明 YouTube OAuth 登录目前不适用；这里的备用方案是不同账号的 Cookie 文件，不能保证永久有效。参考：<https://github.com/yt-dlp/yt-dlp/wiki/Extractors>。

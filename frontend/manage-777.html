HotCopy 全系统标准化运维与应急手册

面对掉线、风控、高并发、账单与集群容灾的标准操作步骤 (SOP)

1

YouTube 凭证失效处理

• 判断状态：“探测通过”只表示当前服务器可访问测试视频；“待检测”不能当作有效。“认证失败”才会触发备用切换；视频下架、地区限制或服务器 IP 问题需单独排查。

• 更新步骤：用对应专用账号打开新的无痕窗口登录 YouTube，在同一窗口打开 youtube.com/robots.txt，导出 youtube.com 的 Netscape 格式 Cookie，然后关闭无痕窗口。选中后台的对应位置，粘贴并保存，再点“检测全部凭证”。

• 维护时机：以实际探测和提取结果为准，不按固定月份推算有效期。不要把 Cookie 粘贴到聊天、工单或代码仓库。

2

服务器三节点心跳与 PM2 进程守护

• 主节点 IP：139.180.190.183（新加坡核心应用网关，端口 3001）。

• 守护命令：主服务使用 PM2 开机常驻，应用名称为 hotcopy-backend。

• 重启与自愈：遇到任何偶发异常，在终端运行 pm2 reload hotcopy-backend 即可实现 0 秒停机无缝热重载。

3

SQLite 核心数据与高价值自媒体 SFT 语料资产

• 数据存储：所有用户、额度及沉淀的清洗后爆款短视频语料存放在 /opt/hotcopy/database.sqlite。

• 导出语料：在「运营总览」中使用「导出 JSONL」。导出前请确认数据使用授权与内容质量。

4

Creem 国际支付网关白帽合规与 Webhook 自动发货规范

• 商品描述：准确描述实际交付的创作与转录功能，避免使用与产品不符的承诺；支付平台审核以其实际规则为准。

• Delivery 字段留空准则：Delivery 用于交付电子书或压缩包下载，HotCopy 属于线上云服务，权益发货完全由服务端实时 Webhook 完成，因此 Delivery 必须保持留空 (Nothing to deliver yet)。

• Return URL (付款成功重定向)：统一填写 https://hotcopy.eazyopc.com/?payment=success，用户在 Creem 刷卡完成后自动跳回主站，主站会自动捕获该参数弹出庆祝通知并自动刷新用户配额。

• Webhook 自动发货端点：在 Creem 的 Developers ➜ Webhooks 中填入 https://api.eazyopc.com/api/webhook/creem，勾选 checkout.completed 与 subscription.created，即可实现毫秒级自动充值发货。

管理入口与访问控制

• 为何废弃常规 /admin 入口？
常见管理路径会被自动化扫描。管理入口仍须依赖服务端鉴权与密码保护。

• 假死 404 伪装机制：
特定入口路径只能减少误访问，不能代替服务端访问控制。

• 你的独享专属管理路径：
https://hotcopy.eazyopc.com/manage-777
建议将此网址加入浏览器私密书签，避免泄露。

会话与 Token 鉴权机制

• 登入后系统颁发 7 天长效 JWT 安全凭据，自动加密存储于浏览器会话中。

• 无论是修改管理员名称还是更新密码，密码均经过工业级 Bcrypt 10 轮加盐哈希 后持久化存入服务器 SQLite 数据库，即便服务器冷重启凭据也绝对不会丢失。
